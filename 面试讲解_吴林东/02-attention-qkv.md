# 第二讲：Q、K、V 与多头注意力

## 先复习第一讲

训练样本把文本切成错位的 `x` 和 `y`，模型在每个位置预测下一个 token。训练时真实的
整段序列已知，所以同一层可以并行计算；生成时新 token 需要一个个确定。今天的重点是
Transformer Block 如何让不同位置交换信息。

## 面试问：Q、K、V 是什么？

参考回答：Q 是当前位置发出的查询，K 是各位置用于匹配的键，V 是被聚合的内容。三者
来自同一输入表示经过不同的可学习线性投影。Q 与 K 的匹配分数决定关注权重，V 按权重
加权求和后形成新的位置表示。

项目把三次线性投影合并为一次：

```python
self.c_attn = nn.Linear(config.n_embd, 3 * config.n_embd)
q, k, v = self.c_attn(x).split(embd_size, dim=2)
```

“一次计算再 split”只是一种实现方式，不表示 Q、K、V 相同；它们对应输出的不同通道和
不同的参数切片。自注意力中的“自”表示三者来自同一条序列，不表示只能看自己。

## 注意力的计算流程

假设当前 query 对两个可见位置的缩放分数为 `[2, 1]`，未来位置被 mask：

```text
scores = [2, 1, -∞]
softmax = [0.731, 0.269, 0]
```

如果两个 value 分别是 `[1, 0]` 和 `[0, 2]`，输出约为：

```text
0.731 × [1, 0] + 0.269 × [0, 2] = [0.731, 0.538]
```

所以注意力不是简单“选一个词”，而是按权重混合信息。项目代码的顺序是：先算 QK 点积，
再除以 `sqrt(head_size)`，然后用下三角 causal mask 屏蔽未来，softmax 得权重，最后用
权重乘 V 得到输出。

## 为什么要除以平方根？

Q 和 K 的点积是多个分量乘积后的求和。头维度增大时，分数的波动通常也会变大。若直接
送入 softmax，分布容易过于尖锐，某个位置几乎拿走全部权重，其他位置的梯度信号变弱。
除以 `sqrt(head_size)` 是尺度控制，让训练初期的分数更适合 softmax。它不只是“防止
溢出”，也不是为了改变分数排序。

## causal mask 为什么必要？

语言模型的第 `i` 个位置只能使用位置 `0..i` 的信息。mask 可以表示为下三角矩阵：

```text
1 0 0 0
1 1 0 0
1 1 1 0
1 1 1 1
```

代码先把禁止位置填成负无穷，softmax 后这些位置的权重为零。这样训练仍能一次算出整
段序列，但不能通过未来 token 偷看答案。训练并行解决的是计算效率，mask 解决的是因果
约束，二者是不同层次的问题。

## 多头注意力改变了什么？

假设 `B=2、T=3、C=8、H=2`，每个头的维度是 `d=C/H=4`。输入形状和拆分大致是：

```text
X                 [2, 3, 8]
Q/K/V             [2, 3, 8]
按头重排          [2, 2, 3, 4]
注意力权重        [2, 2, 3, 3]
各头输出          [2, 2, 3, 4]
拼接后            [2, 3, 8]
```

最后两个维度的 `[3, 3]` 表示每个 query 位置对每个 key 位置的权重。不同头在不同的可学
习子空间中工作，最后再拼接并通过输出投影融合。不能提前规定“第一个头学语法、第二个头
学语义”；这些模式是训练结果，单看某次高权重也不足以构成完整解释。

## 一个 Transformer Block 还包括什么？

项目的 Block 使用 Pre-LayerNorm 和残差：

```python
x = x + self.attn(self.ln_1(x))
x = x + self.mlp(self.ln_2(x))
```

可以把职责分开记：注意力负责跨位置交换信息，MLP 负责对每个位置做非线性变换，
LayerNorm 调整特征尺度，残差保留原表示并提供直接的梯度通路。MLP 先把维度扩大到
`4C`，经过 GELU，再压回 `C`，因此输入输出形状一致，可以与残差相加。

## Q、K、V 与位置编码的关系

默认路径先把 token embedding 和 position embedding 相加，再生成 Q、K、V。开启 RoPE
时，位置旋转施加在 Q、K 上，V 不做同样的旋转。原因是注意力分数依赖 QK 的相对位置
关系，而 V 是要被聚合的内容。面试时要说清项目支持两种位置方案，不要把“位置向量相加”
和“旋转 Q/K”混成一个实现。

## 与 KV Cache 的连接

普通生成每增加一个 token，都重新对完整上下文计算 Q、K、V。缓存路径会保留每层历史的
K、V，只为新 token 计算 Q、K、V，再把新的 K/V 接到缓存后面。项目的
`forward_cached` 还要用绝对位置偏移重新生成 RoPE，并用绝对 query/key 位置构造 mask。
因此缓存不是简单把旧输出存起来，而是保存每一层的注意力键值状态。正确性要求缓存前向
与完整前向的 logits 和 greedy token 一致；项目已有相关数值测试，后续会单独拆解。

## 面试压缩答案

> Q、K、V 由同一输入经过不同线性投影得到，QK 点积决定关注权重，V 按权重聚合。项目
> 用缩放点积和 causal mask 保证未来位置不可见，再通过多头拆分、拼接和输出投影融合。
> 注意力与 MLP 通过 Pre-LN 和残差组成 Block；生成时 KV Cache 保存历史 K/V，减少对旧
> 上下文的重复计算，并用缓存/非缓存一致性测试验证实现。
