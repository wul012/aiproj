# v1320：同样本配对评测的真实运行示例

## 这次解决什么问题

旧评估入口先设种子、再初始化模型、最后抽样。相同种子遇到不同模型宽度，会抽到不同文本窗口。
本版使用独立的窗口计划，两份 checkpoint 共用实际输入和上下文长度，输出逐窗口 NLL 差值。

## 不重新训练，直接复跑

仓库保留了两个约 20 KB 的真实 MiniGPT checkpoint、合成语料和 tokenizer。运行：

```powershell
python -B scripts/evaluate.py --checkpoint f/1320/解释/demo/baseline.pt --compare-with f/1320/解释/demo/candidate.pt --data f/1320/解释/demo/eval.txt --split all --windows 64 --batch-size 8 --device cpu --out runs/paired-demo.json
```

输出 `runs/paired-demo.json` 和 `runs/paired-demo.md`，不覆盖附带的示例结果。

## 结果告诉我们什么

| 指标 | 随机初始化基线 | 同一模型继续训练 40 步 |
| --- | ---: | ---: |
| 平均 NLL（nats/token） | 1.82166194 | 4.57382700 |
| 困惑度 | 6.182124 | 96.914292 |
| 同窗口方向 | — | 28 改善、36 退化、0 持平 |

平均差值（候选减基线）为 **+2.75216506**。训练让候选更擅长 `abc` 模式，但混合评测中的
`cba` 窗口明显变差，最差窗口差值约 +6.4123。新的评测能显示两种方向，而不是只给“训练完成”
或一个无法定位原因的汇总分数。[实际对比明细](demo/comparison.md) · [JSON 全窗口](demo/comparison.json)

**这是故意构造的评测器演示，不是留出泛化实验。** 训练文本和评测中的 `abc` 部分重复，
候选并未接触 `cba` 模式；不能从这个例子推断真实任务效果。未重新计算任何历史科学 verdict。
模型、训练种子和参数见 [provenance.json](demo/provenance.json)。全部文本均为本任务合成，
没有使用个人面试文件或用户私有文本。

## 正确性证据

- 旧代码在模型宽度变化后抽到不同输入，新测试直接记录 forward 输入而非只检查报告字段。
- 均匀 logits 的 NLL 必须等于 log(vocab_size)、困惑度等于 vocab_size；逐 token 手算另作参照。
- 同 checkpoint 自比为零；互换 A/B 后差值反号；改变执行 batch 分组不改变窗口计划。
- 词表语义不一致、上下文超限、验证分片过短、非有限 loss 都不能生成有效比较。
- 固定 demo checkpoint 可在 CI 重跑，无需在测试时重新训练或修改 fixture 来匹配结果。

完整质量门和发布结果分别见本版机器证据与 `v1320.0.0` 标签注释；完整 CI 未通过前不打标签。
