# v1321：总分改善，但别藏起退化的数据组

复用 v1320 的两个固定 MiniGPT checkpoint，本版不重训、不复制模型。两份合成语料分别对应
`abc` 和 `cba` 模式；每组评估相同上下文下的 16 个配对窗口，明确声明 9:1 的权重。

```powershell
python -B scripts/evaluate.py --checkpoint f/1320/解释/demo/baseline.pt --compare-with f/1320/解释/demo/candidate.pt --corpora f/1321/解释/demo/corpora.json --split all --windows 16 --batch-size 4 --device cpu --out runs/corpora-demo.json
```

| 视角 | 基线 NLL | 候选 NLL | 候选减基线 |
| --- | ---: | ---: | ---: |
| forward，权重 9 | 1.826294 | 0.012370 | -1.813925 |
| reverse，权重 1 | 1.810937 | 8.202998 | +6.392061 |
| 两组等权平均 | 1.818616 | 4.107684 | +2.289068 |
| 声明权重下平均 | 1.824759 | 0.831432 | -0.993326 |

**加权总分改善，不等于每个重要数据组都改善。** 报告会列出 `reverse` 退化，并保留两组的
逐窗口损失、位置和片段，不能只挑总分展示。

权重 9:1 是演示政策，不是测量到的真实流量；两组文本是合成模式，也不构成留出泛化实验。
这个例子的目标是验证评估工具能呈现被总分掩盖的退化，不给模型发“整体更强”的证书。
宏平均同样不是唯一正确结论，它只是等权政策下的另一种可解释视角。
