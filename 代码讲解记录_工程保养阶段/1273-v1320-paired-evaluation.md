# v1320：模型比较的第一件事，是让它们做同一份题

## 一、为什么不再继续堆续训护栏

最近几版修复了检查点保存、随机状态、输入校验和数据身份的问题，它们都能保护具体失败路径，但不能直接回答一个更核心的问题：模型改过之后，到底在哪些文本上变好了，哪些地方变差了。用户明确要求把优化重新放回项目重点，因此本版不扩类型检查清单，也不新增发布报告链，而是检查 MiniGPT 的实际评估入口。

这个项目的价值不是把一个很小的模型包装成通用语言模型，而是用自己实现的模型做可信实验。比较对象可以改变宽度、层数或训练阶段，但评估条件必须可对照。若两个 loss 来自不同样本，即使代码完全没有报错，差值仍然混合了模型差异和抽样差异。让比较成立，比再增加一条与实验判断无关的检查更重要。

## 二、旧代码的问题如何复现

原 evaluate.py 在入口设置 Torch 全局种子，随后创建模型、载入参数，最后调用 get_batch 抽取评估窗口。载入参数并不会撤销模型构造时已经消耗的随机数。宽度不同的模型初始化了不同数量的权重，全局生成器的位置因此不同；相同种子并不能保证随后抽到同一份评估数据。

红灯测试创建宽度八和十六的两个模型，使用同样的种子、文本长度、上下文和批量设置，直接记录每次 forward 收到的 token 窗口。旧实现两份输入列表不相等，新实现必须相等。这个测试没有把“报告里的 seed 字段一样”当成证据，因为问题恰恰发生在相同 seed 后面的随机数消耗顺序。判定对象是真实送入模型的数据。

## 三、固定窗口计划从模型中独立出来

新增 evaluation/windows.py 提供一个很小的 WindowPlan：上下文长度、起点序列、可用起点数、请求窗口数和种子。make_plan 使用私有 random.Random 实例从起点范围中采样，不读取或推进 Python、Torch 的全局随机状态，也不需要知道模型宽度。计划一旦建立，两个模型都按同一序列取 x 和右移一位的 y。

窗口起点采用无放回采样，请求数量超过可用起点时评估全部可用起点，不用重复抽同一窗口来伪装成更多样本。起点唯一不代表所有 token 都不重复，因为相邻窗口仍可能重叠。报告因此明确提示窗口间可能相关，不把六十四个窗口称为六十四个独立实验，也不据此给出统计显著性或置信区间。

## 四、上下文长度也必须相同

只固定起点仍不够。如果一个模型使用八个 token 的上下文，另一个使用十二个 token，那么每个窗口的任务不同，平均 NLL 不能被当作完全控制条件下的模型比较。本版默认取两个模型都支持的最小上下文，用户也可以通过 context-size 显式固定一个双方可接受的值。超过任一模型能力就拒绝，而不是偷偷截断其中一个。

同样重要的是 tokenizer 语义。两个模型即便词表大小相同，token 顺序或 BPE 合并规则不同，token 级困惑度也不是同一种计量单位。本版复用已有语义摘要检查，要求配对模型使用相同 tokenizer。它不实现跨 tokenizer 的每字节压缩指标，也不把不同编码下的两个数字硬放进同一张排名表。这是有意识的范围限制。

## 五、计算的是 teacher-forced NLL，不是自由生成质量

score_windows 将同一计划分成若干执行 batch，给模型输入完整窗口，再使用真实右移标签计算 unreduced cross entropy。每个位置得到一个负对数似然，先在窗口内按 token 求均值，再汇总各窗口。窗口长度相同，因此总体平均也就是被评分 token 出现次数上的平均 NLL。最后不足一个 batch 的窗口仍各占相同权重，不会因为分组较小而被夸大。

困惑度通过平均 NLL 的指数得到，不是先计算各窗口困惑度再平均。测试使用均匀 logits 的模型，要求 NLL 等于词表大小的自然对数，困惑度等于词表大小；另一项测试直接从模型 logits 逐位置计算 log-softmax，独立核对新引擎。出现 NaN 或无穷 loss 时拒绝给出有效比较；指数数值过大则在报告中用 null 表示溢出，而不输出不合法 JSON。

## 六、模式切换与执行分组不能干扰结果

评估会暂时将模型切到 eval，关闭 dropout，并在 no_grad 上下文中前向计算。结束或报错时恢复调用前的 train/eval 模式，不为评估留下训练状态副作用。测试检查使用 dropout 的真实模型仍得到稳定结果，并验证评分不消耗 Torch 的全局随机状态。私有窗口生成器同样有独立的状态不变断言。

显式指定 windows 时，batch-size 只决定执行分组，不决定评估集合。把七个窗口分成三个一批或一个一批，起点序列完全相同；浮点计算允许很小的分组数值误差，不把机器精度差异当作模型变化。为了保留旧命令用法，未指定 windows 时，请求窗口数仍等于 eval-iters 乘 batch-size。想跨运行比较或调整执行批量，应显式固定 windows、seed 和 context-size。

## 七、逐窗口差值让结果可行动

evaluation/paired.py 将两列同序损失配对，每条记录包含输入起点、目标结束位置、基线和候选 NLL，以及候选减基线的差值。负数代表候选在该窗口上分配给真实 token 的概率更好，正数代表退化。报告统计改善、退化和数值持平的窗口数，默认把绝对差值不超过百万分之一视作数值持平，而不是实用意义上的等价结论。

JSON 保留全部窗口，Markdown 只展示改善与退化最大的各五项，附上截短后的文本片段，帮助读者定位模式。文本预览只用于阅读，不参与分数计算，完整 token 偏移和数据摘要才是复查坐标。这样的输出让人能检查“总 loss 下降是否掩盖某类文本退化”，不必先手动拼接多个报告，也不只看到一个没有解释的综合分数。

## 八、从真实小模型得到的反例

仓库附带两个很小的真实 checkpoint。基线是固定种子初始化的一层 MiniGPT，候选在同一权重起点上对重复的 abc 模式训练四十步。评测文本混合 abc 和相反顺序的 cba，双方共用六十四个上下文长度为八的窗口。结果不是预设成好消息：二十八个窗口改善，三十六个退化，候选平均 NLL 从基线的约一点八二上升到约四点五七。

逐窗口记录给出原因线索：改善最大的片段包含 abc，退化最大的片段包含 cba。模型的特定模式学习进步，不等于混合数据上整体更好。这个例子让“模型训练了，所以应该更强”的说法遇到可检查的反证。但它仍只是受控演示，abc 的训练模式与部分评测重复，不能作为留出泛化实验或真实业务结论，相关限制明确写在示例入口和来源记录中。

## 九、复跑示例不需要重新训练

演示只保留必要的两个约二十 KB 检查点、tokenizer、合成文本、原始比较 JSON、可读 Markdown 和训练来源参数。用户执行 README 中的一条 evaluate 命令，就能在自己的 runs 目录生成同样协议的结果，不需要先跑四十步训练，也不会覆盖仓库中的示例。CI 直接读取固定模型重新前向评分，数值与归档结果在小容差内一致。

这些文件是最终可复跑材料，不是应被清理掉的临时模型。产生它们的中间脚本、工具安装目录和调试日志则在收尾删除。没有使用用户个人文本，也没有把面试讲解重新上传。对自己的私有评测集运行时要注意，输出报告包含文本片段，不能因为报告看起来像工程日志就默认它适合公开。

## 十、协议变化必须承认

单 checkpoint 入口仍保留 loss、perplexity、tokens、batch-size 等已有字段，但数值采样协议已经改变。旧版是受到初始化影响的随机批次，新版使用 fixed_windows_v1，默认无放回并记录全部起点。因此不能把以前归档的旧 loss 与新 loss 直接作差，声称模型产生了变化；需要对两份 checkpoint 在同一新计划上重新评分。训练过程里的 estimate_loss 和历史科学实验都没有改写。

新版评估的 val 分片也不再在过短时退回 train。评估集不足就报错，避免输出一个标为验证、实际来自训练数据的数值。split all 让用户传入独立评测文件并评分全部内容，但程序并不知道这份文件是否真正没有参与训练。报告记录所选文本摘要、切分偏移、token 数和未知 token 数，同时明确 holdout 来源未验证。这比把输入路径叫作 heldout 就默认可信更准确。

## 十一、哪些检查真正支撑公平比较

测试除了红灯复现，还观察不同宽度和上下文上限的两份 checkpoint 在同一 CLI 调用中收到的实际输入，证明不是两张碰巧相同的计划摘要。自比必须为零，交换两列分数后差值必须反号；预先构造的改善与退化损失检查排名方向和偏移。非有限模型输出、无效上下文、tokenizer 置换和输出路径覆盖输入等情形，不得留下一个看似有效的比较文件。

原有模型 CLI 和架构测试继续运行，不改变旧 fixture 或科学 verdict。新增引擎按职责分成两个小模块，直接服务评分和解释，不额外制造层层报告渲染器。局部类型检查与全仓库门只是交付约束，真正的本版价值证据仍然是固定输入、独立数值参照和那份能展示两种变化方向的真实模型示例。

## 十二、如何使用结论，如何不滥用结论

最强质疑是：同一份题是否就足以证明候选模型更好？还不够。这里只隔离了样本与上下文差异，所选语料代表性、训练数据泄漏、随机训练种子和真实任务指标仍需要独立研究。NLL 改善不自动意味着自由生成更有用；重叠窗口也不允许直接当作独立观测去做显著性声明。本版不发布排行榜，不设置自动晋级 verdict。

实际使用时，先确保两份 checkpoint 的 tokenizer 可比，再明确语料和切分方式，固定 windows、seed 与 context-size，阅读平均差值和两侧最差片段，必要时对不同任务分组另做实验。JSON 保存所有窗口而不是只保留对候选有利的例子，因此别人能反查汇总是否隐去了退化。可复跑、能定位问题、结论有边界，才是这次从机械维护转回项目重点的交付标准。

一句话总结：v1320 让两个模型在同一份可追溯的题目上比较，用真实的逐窗口损失指出改进与退化，而不是用测试数、训练步数或漂亮报告代替模型效果证据。
