# v1321：总分改善，可能正好掩盖你最在乎的退化

## 一、从同样本比较走到分组判断

v1320 解决了两个模型没有做同一份题的问题：评估窗口独立生成，双方使用相同位置、相同上下文和相同 tokenizer 语义。这是比较成立的前提，却还没有回答另一种常见问题：如果评测文本混合了几类任务，一个占比很高的简单类别改善，是否会遮住另一个类别的明显退化？只给混合文件平均值，很容易把两种变化揉在一起。

本版的目标因此不是再设计一套评分算法，而是保留数据组的边界，让结果同时展示各组、等权汇总和明确权重下的汇总。用户可以看到“在哪类数据上变好”“在哪类数据上变差”，以及结论为什么随权重政策变化。它仍然不是模型整体能力判定，也不会自动把候选升级成发布版本；本次发布的是更能支持判断的评估工具。

## 二、一个不用重训的新反例

演示复用 v1320 附带的同一对小模型，不重复训练也不修改旧结果。基线是原始初始化，候选曾在 abc 重复模式上训练。现在将 forward 和 reverse 分成两个文件，分别由 abc 与 cba 模式组成，每组评估十六个窗口。清单声明 forward 权重为九、reverse 权重为一，这只是为了展示混合政策，不是假称观测到了真实使用流量。

实际运行中，forward 的平均 NLL 从约一点八二六下降到零点零一二，而 reverse 从约一点八一一上升到八点二零三。按九比一汇总，总体 NLL 从一点八二五下降到零点八三一，看起来明显改善；给两组相同权重时，平均 NLL 却从一点八一九上升到四点一零八。两种汇总都来自同一批组内评分，不是模型参数再次变化了。

## 三、输入清单表达的是什么

用户给 evaluate.py 增加 corpora 参数，指定一个版本化 JSON 清单。每条记录只需要名称、文件路径和可选权重；权重缺省为一。文件路径相对清单所在目录解析，而不是相对终端当前目录猜测。这样移动整个语料包或从不同位置执行命令时，清单仍然指向同一组输入。名称和解析后的路径不能重复，避免同一份题被无意计算两次。

权重必须是有限正数，布尔值、零、负数或无限值不能进入统计。它不是窗口数量，也不是置信度，更不是由报告器推断的商业重要性。清单的作用是把用户选择的比较政策明文保存下来，而非替用户决定政策。指定 corpora 与指定单份 data 是互斥的，避免两个输入同时出现而其中一个被静默忽略。

## 四、模型只加载一次，评分行为只有一套

原来的单语料计算过程被提取为 _score_corpus。普通评估、单文件模型配对和新的多语料模式都调用它。模型和 tokenizer 在外层只加载一次，多语料分支只是给这个共用函数依次传入不同的数据路径。没有为每个语料再初始化两个模型，也没有用循环启动一批互不知情的命令，然后在文件之间猜测哪些结果可比。

测试用真实加载器记录调用次数，两组语料仍只有基线和候选各一次加载。同时将分组调用里的每个完整组报告，与单独运行该语料得到的报告逐项比较，证明提取没有制造另一种评分方式。底层 WindowPlan、score_windows 和 pair_results 均保持原文件不变，已有同窗口、数值参照和模式恢复检查继续有效。

## 五、组边界不能在抽样时消失

直接把所有语料拼接为长文本，会出现跨文件边界的窗口。例如一个文件末尾的句子可能接到另一领域文件开头，模型实际上在回答数据包中不存在的问题。新模式逐个文件编码、划分和生成窗口，组内的两个模型共用计划，组与组之间不连接。每份文件仍是一份语料，不额外声称文件内部天然就是独立文档边界。

seed、context-size、split 和 windows 等执行设置由一次 CLI 请求确定。每组独立使用相同种子创建计划，清单调换顺序不会消耗前一组留下的随机序列。因此用户只是重排展示顺序，不会意外改掉每组试题。测试会反转清单，按组名比较完整子报告和两种汇总，保护这一点，而不仅检查 seed 字段写得一样。

## 六、宏平均与权重平均不能含混

设每组平均 NLL 为一列数。宏平均就是对组均值等权求平均，回答“把每个数据组看得同样重要时如何”。权重平均按清单权重乘组均值，再除以总权重，回答“按这份声明的混合政策如何”。本版不根据文件长度或采到的窗口数自动改变权重，也没有暗中使用较大文件作为更有权威的样本。

如果某个短语料只有少量可用窗口，它仍按 v1320 的无放回规则评估可用起点，但保留其声明权重。报告展示实际窗口数，让读者知道不同组的样本强度可能不同。等权平均不是统计上自动最优的选择，权重平均也不是天然更接近真实世界；它们是两种明确政策，必须结合数据的代表性和任务目标解释。

## 七、困惑度应当在聚合之后计算

NLL 是对数尺度上的平均损失，困惑度则是它的指数。先平均各组困惑度再声称得到了整体困惑度，会得到不同的量。本版先聚合 NLL，再调用已有的困惑度转换。测试用两组人工可算的损失，要求宏平均和九比一平均都与手算一致，并单独证明结果不等于错误的困惑度直接平均。

权重允许表达较大的正比例数，计算时先除以最大权重再归一化，保持相对比例并避免总权重轻易溢出。把权重九和一同时乘上一个大常数，结果应不变，测试也覆盖这个性质。这是为了保证用户声明同一个比例时得到同一个聚合结果，而不是通过数值尺度不同改变模型比较结论。

## 八、退化清单必须与总分并列

每组沿用候选减基线的 NLL 差值，正值意味着该组上候选更差。汇总始终保留所有超过数值容差的退化组名称，不会因为加权总分为负就删掉它们。若加权平均改善且至少有一组退化，报告会同时标记 weighted_gain_with_regressions，并明确提醒读者不要只展示总分。

这一标记只是逻辑条件，不是统计显著性或实用风险阈值。百万分之一的容差用来避免浮点尾数噪声被称为退化，不表示一个更大的差值就一定重要。用户仍要结合语料类型和应用代价判断。工具负责把不利事实摆出来，不能把一个带提示的报告替代业务判断或模型研究结论。

## 九、报告从全局到具体片段

Markdown 首先列出组名、权重、窗口数、双方平均 NLL 和差值，然后并列显示两种聚合和退化清单。下方复用原来的配对报告，显示每组改善和退化最大的窗口片段。这样读者既能快速定位 reverse 组，也能继续查看它到底在哪些 cba 文本位置上损失升高，不必再手动查找一批不同目录中的输出。

JSON 保留每组完整原始报告，包括文本与 checkpoint 摘要、tokenizer 身份、分片偏移、计划起点和全部窗口分数。组级平均值可以据此反查，演示没有只保存有利窗口。名称经过转义，避免清单里的换行、表格竖线或 HTML 字符破坏报告结构。输出包含语料片段与路径，用户对私有数据运行时仍需自行控制报告的公开范围。

## 十、一个组失败时不能假装评完了

某组缺文件、有效分片太短或清单有错误时，新的多语料命令不会跳过它再输出一个更好看的剩余平均值。所有语料成功评分后才进入最终写出阶段；若第二组失败，已经算出的第一组只存在于内存，没有被当成完整结果发布。测试分别模拟缺文件、短文本和输出路径覆盖输入，检查原有报告与数据字节不变。

这不意味着两个输出文件具有数据库式事务。全部评分完成后，JSON 与 Markdown 仍按现有方式写出，设备或磁盘在写出阶段发生故障不属于本版的全目录回滚承诺。本版保护的是不能把失败组静默从评测对象中拿掉；并发写入、网络存储故障和长期任务恢复需要单独设计，不能靠这条循环自动获得。

## 十一、兼容性与真正的验证证据

新模式是显式开启的，已有不带 corpora 的命令继续走原来的单份评分和报告路径。独立进程对比从 Git 取出 v1320 的 evaluate.py，分别运行旧版与本版的单模型和单文件配对命令，要求 JSON 字节一致，配对 Markdown 也一致。它验证的不只是平均值接近，而是这次提取没有悄悄改变老入口的字段、样本顺序或格式。

分组新功能另有算术参照、清单校验、模型加载次数、组内单独评分一致性和顺序不变测试。演示只读取已经发布的 v1320 checkpoint，不重训、不移动、不改写旧 fixture。CI 可直接重新前向计算得到宏平均变差、加权平均改善和 reverse 退化这三个同时成立的事实。质量门用于防回归，本版价值则来自这些可重复的模型结果。

## 十二、如何避免滥用这项能力

最强的质疑是用户可以调整权重，让喜欢的候选看起来更好。这是真的，所以报告不隐藏权重政策，同时提供等权视角和所有组别结果。权重九比一只代表本示例的声明，不应被引用成测得的流量分布。更换权重后的结论也必须连同政策一起表达，不能说成模型本身突然提升了另一种能力。

合成模式示例不是留出泛化实验，窗口仍然可能重叠，不提供独立性或显著性证明。NLL 评价也不自动代表自由生成体验。真实项目使用时，应先明确语料组与权重的来源，固定评估上下文和采样计划，再同时看宏平均、权重平均与退化组，最后决定是否需要更有代表性的数据或其他任务指标。这一版帮助人看清取舍，而不替人做不透明的自动晋级。

一句话总结：v1321 保留每类语料的独立成绩，把漂亮总分背后的退化放在同一张报告里，让模型比较的结论与其数据和权重政策一起接受复核。
