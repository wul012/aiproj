# 1264 - v1307 归一化迁移试点:机制被证明,约束也被证明(负结果)

## 本版目标与不做什么

优雅收官报告把"扁平 1,355 个模块"列为通往 9 分的**主项**。本版是这条
弧的**试点**,回答两个问题:(1) 迁移到底靠什么让 `flat_dir_file_count`
下降?(2) 能不能一次迁一个模块?**本版最终产出是文档,不是代码**——
试点被完整回滚,仓库停在 v1306。这不是失败,是试点该有的样子。

## 发现一:owner 包现在是**纯门面**,所以指标永远不动

`minigpt/core/model.py` 只有 4 行,是个再导出壳;`core/__init__` 的
docstring 自己写着:"实现仍在历史扁平模块里,本包是物理搬迁之前的
迁移目标"。契约测试更是明文禁止 owner 包子模块里出现实现
(任何 `FunctionDef` 都会被报成 "contains implementation statement")。

**只要子模块全是门面,扁平模块就永远是代码的唯一住处,指标就永远
不会降。** 这解释了为什么 `flat_dir_file_count` 从 v1293 冻结至今
一动没动——不是没人做,是当前契约结构上不允许。

## 发现二:机制成立,且当场量到了

迁移 = 实现搬进 owner 包 + 扁平路径留 `sys.modules` 转发 shim。
优雅棘轮把 shim 排除在 `flat_dir_file_count` 之外,所以指标**恰好**
下降迁移的模块数,同时 `minigpt.model is minigpt.core.model` 仍然成立。

试点迁了 core 的四个原语(tokenizer/dataset/history/rope),
**实测 1,355 → 1,351**;架构测试、shim 身份测试、静态与类型闸门
在那一刻**全绿**。机制没有问题。

## 发现三(致命约束):包不能半迁

紧接着 `test_model` 崩在循环导入,根因是**结构性**的:

```
扁平 model.py  → import minigpt.rope     (已成 shim)
       shim    → import minigpt.core     (触发包 __init__)
core/__init__  → import minigpt.core.model (仍是门面)
core/model.py  → import minigpt.model     ← 正在初始化中
```

owner 包的 `__init__` **急切地**串起所有子模块。于是只要有一个子模块
被迁走、而任何扁平模块又 import 了它,同包里**尚未迁移的门面**就会在
初始化半途回指扁平命名空间,环就成了。

**结论:迁移的最小单位是整个 owner 包,必须原子完成。**

## 这让 core 的真实第一步变成"拆 model.py"

整包迁移意味着 `model.py` 也得进去,而它 **299 行**,owner 包有
**220 行上限**。所以第一步其实是拆分 model.py——而这**不是机械活**:
它就是 Transformer 本体,紧邻科学线;更要紧的是 `GPTConfig` /
`MiniGPT` 的类路径**可能被已保存的 checkpoint 引用**(v1185 那个
canonical grok checkpoint 及其加载器),搬动类会有让既有产物加载不了的
风险。**动手之前必须先拿真 `.pt` 验证这一点。**

在一个已经很长的会话末尾去拆神经网络本体,是我一整轮都在避免的那种
风险。所以本版停在这里,把结论写清楚,而不是硬做。

## 契约要改,但不能白改

完成迁移必然要退役"子模块只能是门面"这条规则——那正是这条规则名字里
`transitional`(过渡)所预告的终点。试点里的替代方案保证**守卫总强度
不降**:门面形制规则继续按**形状**(而非位置)适用于仍是门面的模块;
实现子模块继续受**不变的 220 行上限**与**不变的分层禁令**约束;并**新增**
一条:实现子模块不得再从它被迁出的那片扁平命名空间导入——否则搬迁
只是装样子。

## 工程教训

1. **负结果要留下可复用的部分**:机制(shim 让指标下降)与约束
   (包必须原子迁移)都是硬知识,写进
   `docs/elegance/normalization-migration-design.md`,下一次可以直接
   从第 2 步开始,不必重踩。
2. **回滚要看索引不是工作树**:第一次回滚没干净,因为迁移脚本对新文件
   跑过 `git add`,`git checkout --` 是从**索引**恢复的,于是把迁移后的
   内容又写了回来。正确做法是先 `git reset` 再 checkout。
3. **诚实的量级比乐观的方向重要**:即便 core 整包迁完,1,355 也只降到
   1,350。真正能撬动"导航"这一分的,是那 ~500 个逐版本生成的治理产物
   模块——而对它们更该问的问题是"迁移还是**归档出 src**",那是产品
   决定,不是工程决定。

产物:`docs/elegance/normalization-migration-design.md`(机制、约束、
契约改法与推荐顺序);本讲解。代码零改动。
