# 1263 - v1306 符号改名批 2:链形家族收尾 353 符号,存量 6,494 → 6,141

## 本版目标与不做什么

把 v1305 的规则推广到**其余链形家族**(packet_chain / registry_ack /
ack_bundle / target_hidden 系列)。这些家族与 receipt_chain 同型:
生成式的 `build/render/write_*` 加一组 `*_FILENAME` 常量。结果:
**353 个符号**改名、190 个文件改写;**59 个模块(398 个符号)被排除**
——排除率超过一半,这个数字本身是本版最重要的结论(见末节)。
不做什么:不碰 model_capability / bounded_objective 两大族(1,529 +
447,形状不同,需要各自的规则);不碰 1,610 条 `filename` 违规。

## 两条新的正确性约束(都是断言先抓到的)

### 1. 派生必须以"定义处"为准,而不是"引用处"

生成器最初按"模块 → 该模块出现的长名"派生短名。断言当场炸出矛盾:
同一个长名 `locate_..._receipt_packet` 在 `registry_ack_packet_check`
和 `registry_ack_packet_index` 两个模块里都出现,于是被要求同时叫
`locate_ack_packet_check` 和 `locate_ack_packet_index`。

原因是这些符号**定义在一个模块、被另一个模块 import**。修法:先建
**定义索引**(全仓扫描顶层 def/assign),短名一律从**定义所在模块**
派生;若一个名字在多个模块里都有定义(去重弧遗留的真重复),则
**判定为歧义、整体排除**(本批 27 个)。

### 2. 塌缩后的核心必须全局唯一

第二次断言炸在目标撞名:`registry_ack_packet_artifacts` 丢掉
`registry`、`ack_bundle_packet_artifacts` 丢掉 `bundle`,**双双塌缩到
同一个核心** `ack_packet_artifacts`,于是两个不同模块的符号会被改成
同一个名字——那是把两个东西合并成一个,比长名危险得多。修法:核心
选择改为**先到先得的认领制**——按候选(从长到短)选第一个"既满足
预算、又未被认领"的核心;若全部候选都被占用或都超预算,该模块**排除**。

## P1 的精化:被屏蔽的模块路径是合法幸存者

应用后 P1 报了两个"旧名仍然存在":
`scripts.build_randomized_target_hidden_holdout_suite`。查证后确认这是
**第 9 类耦合的护栏在正常工作**——脚本以它包装的函数命名,那串长名
此刻是**模块路径**,改它属于文件改名弧,不属于符号改名弧。

于是 P1 精化为:旧名**只允许**作为 `minigpt./scripts./tests.` 后的
点分路径片段幸存,其余任何标识符位置的幸存都是遗漏。精化后
**非模块路径幸存 = 0**;P2 以 git HEAD 为基线对照 **3,214 个文件**的
字符串常量,**零个产物值变化**。

## 结论:通用规则到此为止

**排除率 53%** 是本版的真结论。前两批(试点 + receipt_chain)排除率
接近零,本批过半——说明链形家族的同质性已经被吃干净,剩下的
4,500 余条违规**不再服从同一条规则**:形状不同、冗余词不同、
定义/引用关系更复杂。继续用通用生成器只会让排除率继续升高。

因此符号弧的下一步不是"再跑一次生成器",而是**按家族重新设计规则**
(model_capability_required 1,529 条是最大的一族,值得单独一版),
或者先处理那些**结构性**的遗留(27 个歧义符号 = 去重弧没吃掉的真重复;
75 个大小写别名 = 死代码)。这两类都不是改名问题,是**清理**问题。

## 工程教训

1. **符号的身份属于它的定义处**:任何跨模块的改名,派生依据必须是
   定义点。按引用点派生,在单模块家族里侥幸正确,在跨模块家族里
   必然矛盾——而矛盾还好,静默合并才致命。
2. **塌缩必须认领**:两条不同的塌缩路径可能撞到同一个短名。名字的
   唯一性要在生成期用认领制保证,不能靠事后去重(事后去重会让
   "谁该改名"变成任意选择)。
3. **排除率是规则适用性的温度计**:0% 说明规则贴合,53% 说明规则
   已经用到了边界。指标该停在哪里,由排除率说了算,不由目标数字说了算。
