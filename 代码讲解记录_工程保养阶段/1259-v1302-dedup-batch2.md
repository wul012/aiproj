# 1259 - v1302 去重批 2:79 簇 502 份并入 22 个宿主,重复存量 204 → 125

## 本版目标与不做什么

去重弧第二批。批 1 只用了两个 report 公共宿主;本批把范围扩到
**22 个宿主**,核心是一条新的路由规则:**按依赖方向选宿主**。
`locate_*` 家族(每个函数只做一件事:把目录路径补成该家族的产物
JSON 全名)的自由名是某个常量,而那个常量的所有者模块**成员早已
import**——所以函数应当搬进常量的所有者,而不是搬进公共模块。
这样零新增依赖边、零环风险,且读者在"谁定义文件名"的地方
找到"谁解析文件名"。其余簇按批 1 规则进 report_utils /
report_check_common。不做什么:`_style` 家族(27 个变体、650 行 CSS)
继续挂起——塞进公共宿主会撞 800 行硬顶,它的正确归宿是归一化后的
reports 包;多变体家族与 BLOCKED 簇留给批 3。

## 批 1 的二阶效应:解锁

批 1 抽走 `_check` 之后,`_field_checks`(41 份)的自由名 `_check`
在所有成员里变成了**同一条 import**——它从批 1 的 BLOCKED 变成本批的
可抽取。这是预判过的二阶效应第一次兑现:去重不是一次性筛选,是
**分层剥洋葱**,每剥一层,下一层的依赖就变整齐一次。批 3 的候选
将再次由本批的结果决定,而不是由一份静态清单决定。

## 度量的盲区:同体不同名,算两簇

收尾时 name-budget 闸门拦下 7 个新违规,全是本批新铸的 `locate_*`
公共名超 40 字符。顺着查下去,查出一件比闸门本身更重要的事:
两个宿主里"两个不同的簇",函数体**逐字节相同,只有函数名不同**
——`dup_def_stock` 用 `ast.dump` 计数,而 `ast.dump` 含函数名,
所以**同体不同名被算作两个簇**,我照着计划真的建了两个一模一样的
函数。正确的收尾不是给长名换底(rebase 工具会拒绝:新 7 ≠ 消解 24,
它只证明纯改名的中性),而是:

1. 两个宿主各自**塌缩成一个函数**(成员用 `as` 保住各自的旧局部名,
   调用点零改动);
2. 五个单名宿主的公共名**去掉与模块名重复的前缀**(模块已经说明了
   领域:`randomized_target_hidden_holdout_suite.locate_holdout_suite`)。

于是没有任何新违规产生,24 个消解**全额入账**:name-budget 存量
**7,515 → 7,491**——这是该指标的**首次真实下降**(此前五批改名
全部是零净换底)。

## 对抗式自检抓到的两处

塌缩脚本第一遍在"已迁移"判定上用了**按名字建的 dict**,把同名的
两个 def 折叠成一个,于是误判宿主已完成、跳过——留下两个同名 def。
ruff 的 F811 当场点名。修完之后不满足于"这次好了",写了一个
**全仓对抗式扫描**:任何模块不得重复定义同一个顶层名。结果扫出
**第二处**,且 `git stash` 验证是**先于本版就存在**的(
`benchmark_scorecard_artifacts._string_list` 定义两次,第一份是死代码
被第二份完全遮蔽)。两处一起修掉,并把这条扫描**升级为常驻测试**
——它能看见 `dup_def_stock` 结构上看不见的东西:重复度量比较的是
**跨模块**的函数体,模块**内部**的自我遮蔽不在其视野里。

## 工程教训

1. **依赖方向决定宿主**:公共模块不是唯一答案。当被抽取函数的自由名
   有明确所有者、且成员已依赖该所有者时,搬进所有者更便宜也更好读。
2. **度量有盲区,且盲区可被脚本继承**:`ast.dump` 含函数名 → 同体
   不同名算两簇 → 计划照单全收 → 真的造出两个同函数。指标是路标
   不是判官,执行前要问"这两簇为什么不同"。
3. **闸门拒绝时,先问能不能不产生违规**:换底工具是为纯改名准备的;
   本批的正解是把新名铸造在预算内,顺带把 24 个消解全额兑现——
   绕过闸门与满足闸门之间,永远先试第三条路:让问题不发生。
4. **修完一处,扫全仓**:同一错误形态在别处已经存在了多久没人知道
   ——一次对抗式扫描 + 升级为常驻测试,比修一处便宜得多。
